### 1. B2B API Integration Guide (Partner-Facing)

This document is designed to be handed directly to your partner’s engineering team. It treats your risk engine entirely as a "black box," exposing only the required inputs (account numbers) and outputs (risk verdicts) without revealing your internal algorithms, scoring matrix, or database architecture.

---

**Overview**
The AG SHIELD API provides real-time risk assessment and identity resolution for bank accounts. By submitting an account number and bank code, the API returns an automated safety verdict, a confidence score, and associated threat intelligence.

**Authentication**
All requests require a Bearer token passed in the `Authorization` header.

* **Header Format:** `Authorization: Bearer <YOUR_B2B_API_KEY>`
* Keys are bound to specific monthly quotas and rate limits. Keep your key secure.

**Base URL**
`[https://api.agtechafrica.com/v1](https://api.agtechafrica.com/v1)` *(Update with your production domain)*

**Endpoint: Account Risk Scan**
`POST /risk/scan`

Evaluates a specific account against the risk engine.

**Request Body (JSON):**

```json
{
  "account_number": "0123456789",
  "bank_code": "044"
}

```

* `account_number` (String, Required): The 10-digit NUBAN to evaluate.
* `bank_code` (String, Required): The canonical 3-digit or 6-digit bank routing code.

**Successful Response (200 OK):**

```json
{
  "status": "success",
  "data": {
    "account_number": "0123456789",
    "resolved_name": "JOHN DOE",
    "verdict": "REVIEW",
    "risk_score": 75,
    "confidence_level": 0.85,
    "risk_factors": [
      {
        "tier": "OSINT",
        "agency": "CROWDSOURCED",
        "reason": "Reported for non-delivery of goods."
      }
    ]
  }
}

```

**Response Data Dictionary:**

* `verdict`: The recommended action. Returns `SAFE`, `REVIEW`, or `BLOCK`.
* `risk_score`: A normalized integer (0-100) indicating the threat level (higher is more dangerous).
* `confidence_level`: A decimal (0.0 to 1.0) indicating the system's certainty based on available data history.
* `tier`: Indicates the source authority (`OFFICIAL` or `OSINT`).

**Error Handling:**

* `400 Bad Request`: Invalid input (e.g., non-10-digit account number).
* `401 Unauthorized`: Missing or invalid API key.
* `403 Forbidden`: API key lacks required scopes.
* `429 Too Many Requests`: Monthly quota exceeded.
