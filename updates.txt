- lookup_cache_refresher.py uses asyncio.sleep(0.4) to pace ~50 upstream

  Python process). If the host sleeps/reboots/terminal closes, the worker

  keep local runner for now (per project decision), but add a local

3) THE SIX CRITICAL VULNERABILITIES (lines 9-111)

#1 Bank Code Discrepancies & Cache Key Pollution (VALID)
- bank_lookup_cache key is (account_number, COALESCE(bank_code,'')) and
  uq_bank_lookup_cache_key enforces that exact pair. Bank codes vary
  (044/000014, 090110/50515). Example consequence: query 044 cached,
  000014 treated as miss -> duplicate upstream calls + duplicate rows.
- Fix: centralized Bank Code Normalization (canonical code ← NIP 3-digit
  or 6-digit, provider codes, bank name aliases) in Postgres before
  insert/query. Normalize on write and read; use canonical id/code.

#2 Inflated "Confidence Score" Fallacy (VALID)
- Zero-history checks can return Verdict: safe, Score: 25/100,
  Confidence: 0.75 (75%). High confidence requires abundant proof; zero
  history must be low confidence.
- Fix: baseline confidence <= 0.35 for zero-history; scale upward only
  with clean history, multi-source corroboration and accumulated
  evidence. Treat unresolved holder identity as a strong confidence
  penalty (never allow "safe" with high confidence on unverified
  identity).

#3 Title Noise & Multi-Token Name Evasion (VALID — WORSE)
- Paystack names include honorifics (ALHAJI, DR., CHIEF, MRS., MR).
  Token reordering/permutations and extra noise tokens can drop trigram
  scores below 0.85 or push matches into the wrong band. This is
  compounded by severity masking (see #7).
- Fix: name sanitization pipeline: strip common Nigerian titles (Alhaji/
  Hajia, Chief, Dr/Ph.D, Pastor/Prophet, Imam, Engr, Barr, Mr/Mrs/Ms),
  collapse whitespace, strip punctuation, normalize case, and also
  consider token-order-insensitive comparison (e.g. sort tokens). Keep
  index-backed (GIN trgm) matching.

#4 Upstream Quota Drain via Input Manipulation (VALID)
- Variants ("8165764169","08165764169"," 8165764169 ") create cache miss
  (exact string equality on account_number). resolve-account/index.ts
  uses the raw account_number (lines ~106,115) with no normalization or
  NUBAN validation. Can exhaust Paystack quota quickly.
- Fix: TRIM, strip non-digits, normalize leading zeros to standard
  10-digit NUBAN where applicable, reject invalid formats at the Edge
  Function boundary before DB/upstream calls. Normalize in SQL too
  (shared invariant).

#5 Unindexed Rolling Velocity Query Bottleneck (FACTUALLY WRONG)
- goals.txt states velocity reads global_risk_evaluations for counts in
  last 48h on an account. Live schema: global_risk_evaluations has NO
  account_number column (columns: id, channel, tenant_id, queried_name,
  bank_name, evaluated_score, verdict_level, reasons, recommended_action,
  source_registry, execution_time_ms, created_at). Existing indexes:
  idx_eval_created, idx_eval_queried, idx_eval_tenant_channel.
- The velocity signal in the engine reads reports (and/or user_checks)
  as appropriate. reports already indexed (account_id, created_at DESC),
  idx_reports_account_created on (account_id, created_at DESC). No
  current unindexed bottleneck exists for this specific claim. No
  action required for this claim as written.

#6 Broken Tier 1 Moat: Missing Realtime Alert Engine (VALID)
- No database trigger to cross-reference user_checks when an account is
  later added to registry_blacklist and notify affected users. The
  "Realtime Alert Safeguard" is not implemented.
- Fix: reuse existing notifications table (not auth.users scan). Scope
  alerts to affected user_checks (e.g. rows that checked that account
  within a retention window) and populate via trigger or idempotent job.
  Do NOT SELECT FROM auth.users to broadcast to all users.

4) SEVERITY MASKING BUG DISCOVERED (NOT IN GOALS LIST)
Reproduced live via screen_person_name:
- 'MR UMAR ABDULLAHI' → 5 rows returned; PEP 'Abdullahi Umar' 83 is
  first, SANCTIONS 'UMAR ABDULLAHI' 83 is third → engine exits on first
  row -> REVIEW instead of BLOCK.
- 'ALHAJI UMAR ABDULLAHI' and 'ALHAJI DR UMAR ABDULLAHI' same masking.

titles. Root cause: 7c loop exits after the first candidate (ordered by
raw score). Fix: rank by agency severity (SANCTIONS > INTERPOL > PEP >
other) then score DESC, and evaluate the worst-agency match (or return
all and pick highest-severity). Keep matching index-backed.
